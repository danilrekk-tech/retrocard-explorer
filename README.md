# Retro Console Hub

RetroCard — интеллектуальный менеджер SD-карт для ретро-консолей

Создай полноценный современный web-сервис под названием RetroCard.

Главная идея: сервис помогает владельцу ретро-консолей привести microSD-карту в порядок, проверить её содержимое и подготовить её для использования в приставке.

Первоначально ориентируйся на Anbernic RG353V, но архитектуру сделай так, чтобы позже можно было добавить другие приставки.

Основные возможности

1. Dashboard

Главный экран должен показывать состояние подключённой SD-карты:

объём;

свободное место;

занятое место;

количество игр;

количество систем;

BIOS;

сохранений;

artwork;

найденные проблемы.

Сделай понятный визуальный индикатор состояния карты.

Например:

SD Card Health — Good / Warning / Critical



2. Подключение SD-карты

Предусмотри интерфейс подключения локального помощника, который в будущем будет установлен на компьютере пользователя.

Пока реального помощника нет — используй Mock Data, чтобы весь интерфейс можно было полноценно протестировать.

Показывай:

Local Agent

Connected

Disconnected

И кнопку:

Connect



3. Анализ карты

Создай полноценный экран:

SD Card Analyzer

Он должен показывать:

найденную прошивку;

структуру папок;

количество файлов;

ROM;

BIOS;

saves;

artwork;

неизвестные файлы;

потенциальные проблемы.

Поддержи как минимум:

ArkOS;

Stock OS;

JELOS;

ROCKNIX;

Unknown.



4. ROM Library

Создай красивую библиотеку игр.

Группировка по системам:

NES

SNES

Game Boy

Game Boy Color

Game Boy Advance

Mega Drive

Genesis

Nintendo 64

PlayStation

PSP

Arcade

другие найденные системы.

Для каждой игры показывай:

название;

систему;

файл;

размер;

формат;

регион, если известен;

artwork;

статус;

наличие проблем.



5. Organizer

Главная функция сервиса:

Organize SD Card

Сервис должен анализировать текущую структуру карты и предлагать, куда должны находиться файлы.

Например:

Pokemon.gba

→ GBA

Mario.zip

→ NES

Tekken.bin

→ PlayStation

Пользователь должен сначала увидеть Preview изменений.

Только после подтверждения должна выполняться операция.



6. Duplicate Finder

Создай раздел поиска дубликатов.

Показывай:

точные дубликаты;

потенциально одинаковые игры;

разные версии;

разные регионы.

Ничего не удаляй автоматически.

Пользователь сам выбирает, что удалить.



7. BIOS Checker

Создай отдельный раздел:

BIOS

Показывай:

найденные BIOS;

отсутствующие BIOS;

BIOS, которые не используются;

для каких систем BIOS может потребоваться.

Не скачивай BIOS и не используй нелегальные источники.



8. Collection Cleaner

Создай инструмент очистки коллекции.

Фильтры:

система;

регион;

язык;

дубликаты;

неизвестные файлы;

artwork;

версии игр.

Перед изменениями показывай:

Before / After

и предполагаемое освобождение места.



9. Backup

Создай:

Backup Center

Пользователь должен иметь возможность создавать резервную копию важных файлов перед изменениями.

Показывай:

дату;

размер;

количество файлов;

статус.



10. SD Card Setup

Добавь режим:

Prepare New SD Card

Пользователь выбирает:

консоль;

прошивку;

размер карты.

Сервис создаёт рекомендуемую структуру папок.

Например:

ROMs

├── NES

├── SNES

├── GBA

├── N64

├── PSX

├── PSP

└── ...

Пользователь сможет скачать подготовленную структуру.



11. Migration

Предусмотри раздел:

Migrate SD Card

Например:

ArkOS → ROCKNIX

или

Stock OS → ArkOS

Показывай предполагаемые изменения структуры и предупреждения.

Пока можно реализовать демонстрационный режим.



12. Settings

Создай настройки:

Local Agent;

безопасность;

backup;

правила организации;

системы;

artwork;

интерфейс.



Дизайн

Сделай интерфейс как премиальный инструмент для управления ретро-консолями, а не как обычную админ-панель.

Стиль:

современный;

минималистичный;

технологичный;

немного retro-tech;

аккуратный;

профессиональный.

Используй:

красивые карточки;

таблицы;

progress bars;

status indicators;

file tree;

system icons;

charts там, где они действительно полезны.

Сделай desktop-first интерфейс, но с хорошей адаптацией.



Важный принцип

На первом этапе сервис работает на Mock Data.

Не нужно пытаться получить настоящий доступ к SD-карте через браузер.

Создай реалистичный Mock Layer, имитирующий:

подключение SD;

сканирование;

обнаружение игр;

определение прошивки;

поиск дубликатов;

BIOS;

создание organization plan;

выполнение операций;

progress.

Все действия должны выглядеть так, будто сервис действительно работает с SD-картой.



Архитектура

Используй ту архитектуру и технологии, которые считаешь наиболее подходящими для Lovable.

Главное — чтобы код был:

чистым;

модульным;

хорошо структурированным;

легко расширяемым;

готовым к подключению внешнего Local Agent в будущем.

Не создавай сложную инфраструктуру без необходимости.

Сделай отдельный слой/модуль для взаимодействия с локальным помощником, чтобы позже его можно было заменить с Mock Data на настоящий Local Agent.



Важное требование на будущее

Этот проект позже будет дополнен отдельным RetroCard Local Agent для Windows.

Local Agent будет написан отдельно с помощью Claude Code после того, как будет изучен код этого проекта.

Поэтому:

не делай жёсткую привязку к Mock Data;

отдели UI от операций с файлами;

вынеси взаимодействие с локальным компьютером в отдельный сервисный слой;

используй понятные TypeScript types;

документируй основные интерфейсы;

не помещай логику работы с файлами непосредственно в UI-компоненты.

Создай README с описанием проекта и основных частей архитектуры.



Результат

В результате должен получиться красивый работающий MVP RetroCard, который уже сейчас можно открыть и протестировать с демонстрационной SD-картой.

Пользователь должен пройти полный сценарий:

Connect → Scan → Analyze → Review Problems → Organize → Confirm → Complete

При этом всё пока работает на Mock Data.

В будущем Mock Layer будет заменён настоящим RetroCard Local Agent, который получит доступ к реальной microSD-карте на компьютере пользователя.
